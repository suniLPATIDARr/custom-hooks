Next.js - Complete Guide

1. Overview

Next.js is a popular React framework developed and maintained by Vercel. It extends React by providing powerful features out-of-the-box to build fast, scalable, and SEO-friendly web applications. It handles both client-side and server-side rendering, static site generation, routing, and much more.

2. Why Next.js?

While React is a library focused on building UI components, it does not provide a full solution for:

  • Routing
  • Server-side rendering (SSR)
  • Static site generation (SSG)
  • API routes
  • SEO optimization

Next.js fills these gaps with conventions and built-in features that streamline development and performance.

3. Key Features

a. File-Based Routing

  • Pages are React components stored in the pages/ directory.
  • Each file automatically becomes a route.
  • Nested folders create nested routes.
  • Example: pages/about.js → /about

b. Server-Side Rendering (SSR)

  • Generates HTML on the server on each request.
  • Useful for dynamic data fetching and SEO.
  • Implemented via getServerSideProps function in pages.

c. Static Site Generation (SSG)

  • Pre-renders pages at build time.
  • Great for blogs, marketing sites, documentation.
  • Implemented with getStaticProps and optionally getStaticPaths (for dynamic routes).

d. Incremental Static Regeneration (ISR)

  • Allows updating static pages after build without full rebuild.
  • Set revalidation time to regenerate pages on-demand.

e. API Routes

  • Define backend API endpoints inside the pages/api/ directory.
  • Serverless functions handle HTTP requests.
  • No separate backend server needed for simple APIs.

f. Image Optimization

  • Built-in <Image /> component optimizes images for size and format.
  • Supports lazy loading and responsive images.

g. Automatic Code Splitting

  • Only loads JavaScript needed for the current page.
  • Improves initial load time.

h. Built-in CSS Support

  • Supports global CSS, CSS Modules, and popular CSS-in-JS libraries.
  • Also supports Tailwind CSS integration easily.

i. Fast Refresh

  • Instant feedback during development.
  • Maintains component state on edits.

j. TypeScript Support

  • Built-in support with zero configuration.

k. Middleware & Edge Functions

  • Run code before requests are completed.
  • Great for authentication, redirects, and more.

4. How Next.js Works

When a user visits a page:

  • If SSR is used, server renders HTML with React and sends it.
  • If SSG is used, a pre-built static HTML file is served.

Hydration occurs client-side: React attaches event listeners.

Client-side navigation uses fast route changes without full reloads.

5. Basic Next.js Project Structure

my-next-app/
├── pages/
│   ├── index.js         # Homepage
│   ├── about.js         # About page
│   ├── api/
│   │   └── hello.js     # API route
├── public/              # Static assets like images, favicon
├── styles/              # CSS files
├── next.config.js       # Configuration file
├── package.json

6. Example: Simple Page with Static Props

// pages/index.js
export async function getStaticProps() {
  return {
    props: {
      message: "Hello from Next.js!"
    }
  };
}

export default function Home({ message }) {
  return <h1>{message}</h1>;
}

7. Routing

  • Use <Link href="/about"><a>About</a></Link> for client-side navigation.
  • Supports dynamic routes: [id].js to handle paths like /post/123.

8. API Routes Example

// pages/api/hello.js
export default function handler(req, res) {
  res.status(200).json({ message: "Hello from API" });
}

9. Deployment

  • Deploy to Vercel (creator of Next.js) with zero config.
  • Also works with platforms like Netlify, AWS, and traditional servers.
  • Supports serverless and edge deployments.

10. Advantages

  • Better SEO with SSR and SSG.
  • Faster performance and smaller bundles.
  • Easier developer experience with conventions and tooling.
  • Flexibility to choose rendering strategies per page.
  • API routes allow simple backend logic inside the same project.

11. Use Cases

  • Blogs, marketing websites
  • E-commerce stores
  • Dashboards and admin panels
  • Any React-based web app needing SEO and fast load

12. Limitations

  • SSR increases server load.
  • Learning curve for rendering strategies.
  • More complex build system than CRA (Create React App).
  • Less control over webpack without config.

13. Comparison with Create React App (CRA)

Feature Create React App Next.js
Rendering Client-side only SSR, SSG, ISR, Client-side
Routing Manual setup File-based automatic routing
SEO Difficult Excellent out of the box
API backend Separate server required API routes built-in
Deployment Static hosting Supports static & serverless
